# Input for rewriting the main skill

The core opportunity is **clearer task decisions and completion criteria**, while preserving the short recipes that already work. The evidence does not justify replacing everything with more rules, removing rare sections because they were unused, or banning verification.

This brief is empirical context for a separate writing agent. It does not supply the new wording. [Full report](REPORT.md) · [section matrix](skill/coverage-matrix.md) · [methods](METHODS.md).

## The findings to carry into the rewrite

**1. Preserve the efficient paths.** Across all nine completed benchmark cohorts, Astra's selective-commit, multi-amend and split scenarios repeatedly use approximately 2, 5 and 7 non-guide native calls. Both providers have successful short examples. Donated ordinary website work independently shows `but diff` followed by selected `but commit -b` creating the branch and commit. The inspection choice, IDs, source/target roles, implicit branch creation and order of operations are useful information. [Benchmark evidence](benchmark/benchmark-findings.md); donated [C12](donated-other/evidence-cases.md#c12--efficient-two-command-selected-commit-exists).

**2. The biggest current Astra gap is audit depth.** After the last successful mutation, inspections appear in 193/377 complete Astra trials and 195/377 Fable trials. That near equality hides a large difference: Python-driven Git subprocesses appear in 127 Astra trials versus one Fable trial. Reorder is especially clear: all 24 completed stub/candidate Astra repetitions audit original/reordered commit patches and messages; none of five full-skill baseline repetitions do. Some other Python comparisons directly answer the task. The writing problem is when evidence is sufficient, not whether Python or verification is inherently bad. [Detailed evidence](benchmark/benchmark-findings.md).

**3. Give state concepts priority over extra flag lists.** Fable's actual protocol failures include raw `git fetch` and attempts to repair Git's index after a successful But recovery. But pending changes and an ordinary Git index are different state questions. However, an explicit request for an unstaged file or a clean checkout after teardown makes Git inspection relevant. A blanket “ignore Git status” would be wrong. Source/target direction, selector lifetime and workspace mode are similarly important. [Failure cases](/Users/kiril/tmp/but-skill-evidence-2026-09-10/benchmark/failure-index.json); [content audit](skill/content-audit.md).

**4. Completion includes the effects of verification.** All eight state failures in the 754 completed But trials are Fable selective-copy cache residue; another occurs in stopped i07. No protected-history check fails in these cases. Across the 29 completed copy trials per provider, Astra always submits no-bytecode verification; Fable passes with suppression, scoped cache cleanup, or testing only in a temporary extraction. Its eight failures use neither suppression nor workspace-cache cleanup. One agent sees the cache and leaves removal to the user; another checks before tests and misses what tests create. The general property is preservation of the requested final workspace, not a Python-specific rule or permission for broad cleanup. [New analysis](data/copy-side-effects.md).

**5. Keep selector grammar concrete.** Donated paired error/recovery sequences show incomplete hunk IDs, omitted disambiguating suffixes, an absent amend target, unsupported diff argument cardinality, and Git/gh-style flag guesses. Historical CLI migrations also appear in both directions. Retain the few semantic distinctions needed to choose valid commands; do not bring obsolete syntax back into the core. [Claude/Pi casebook](donated-other/evidence-cases.md); [Codex casebook](donated-codex/evidence-cases.md).

**6. Delivery and instruction quality are different.** Early Fable full-guide requests often clipped the actual command output before saved-file handling. Later core delivery fixed that observed mechanism, yet extra audits persisted. Whole guide exposure is not proof of adoption; a normalized-result omission is not proof the guide was absent. Avoid explaining all excess work as `--full`, and avoid growing the core to compensate for a transport problem. [Benchmark delivery findings](benchmark/benchmark-findings.md).

**7. A shorter core is plausible, but deletion claims remain hypotheses.** The current body is 3,591 words. Command Patterns and the Git-to-But map overlap recipes/reference, while update and conflict sections give different default resolution routes. Evaluate consolidation while preserving semantics. Publication, dependency conflicts, worktrees, collaborators and rare resolution cases are incompletely covered by the benchmark; real donated cases establish some of their relevance. No line or section has been causally ablated. [Allocation and consistency audit](skill/content-audit.md); [coverage matrix](skill/coverage-matrix.md).

## Provider distinction worth retaining

Astra completes the requested state in all 377 complete But trials; its sole strict failure is a frozen guard rejecting read-only reflog. Its larger issue is elaborate preservation audits and occasional irrelevant repair attempts. Fable is generally shorter but has eight actual final-state failures and nine additional strict failures with correct final state, including one malformed-command guard case. These are patterns in this corpus, not enduring traits of the model families. Both providers benefit from the same clear operation and state semantics. [Reconciled outcomes](benchmark/benchmark-findings.md).

The donated corpus supplies older-model usage, not a fresh Astra/Fable 5.1 replication. It also contains substantial benchmark/development material. Use ordinary paired examples as corroboration, not every donated file as an independent real-world validation.

## What the evidence cannot decide for you

It cannot rank individual sentences by causal value, measure hidden reasoning, prove rare sections obsolete, or establish that the short sentence recently added to the stub independently improved results. The complete i06 cohort passed all 78 trials but Astra still had more native calls and higher mean time than baseline; i07 was stopped at 58/78 and is not a parity result. The copy ultimately put in the PR was not tested in isolation.

A future evaluation should retain fast-path correctness, exact preservation, policy compliance and cleanup as separate outcomes; measure model calls as well as native commands; compare both providers and both delivery modes with frozen product/reference/top-level instructions. Add targeted coverage for dependency refusal, publication and mode transitions before deleting their guidance. This is an evaluation suggestion, not a request to restart the stopped loop.
